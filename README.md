# 정상JLS 어휘 단어장·시험지

영어 지문 파일에서 표제어를 골라 **파생어 · 유의어 · 반의어**가 붙은 심화단어장을 만들고,
그 단어장으로 **어휘 시험지**까지 만드는 로컬 앱.

AI 생성은 Anthropic API 키 없이 **이 PC에 로그인된 Claude Code 구독 계정**으로 동작한다.

---

## 실행

[start.bat](start.bat) 을 더블클릭한다. 서버가 켜지고 브라우저가 열린다. 창을 닫으면 종료된다.

이미 켜져 있는 상태에서 다시 눌러도 서버가 하나 더 뜨지 않는다. 브라우저만 새로 연다.
패키지 목록(`package-lock.json`)이 지난번 설치 때와 다르면 서버를 켜기 전에 알아서 다시 설치한다.
켜져 있는 동안 목록이 바뀌었으면(켜 둔 채 `git pull` 한 경우) 창을 닫고 다시 실행하라고 알린다.

바탕화면에서 바로 열려면 `start.bat` 을 오른쪽 클릭 → **바로 가기 만들기** 로 만든 뒤 바탕화면으로 옮긴다.

터미널로 직접 실행할 수도 있다.

```bash
npm install
npm run dev
```

브라우저에서 안내된 주소(기본 http://localhost:5180)를 연다.

### 사전 조건

- Node.js 18 이상
- Claude Code CLI 설치 및 로그인 — 터미널에서 `claude --version` 이 실행되어야 한다.
  - **2.1.280 이상**이어야 기본 모델(Opus 5.5)을 쓸 수 있다. 낮으면 터미널에서 `claude update` 를 실행한다.
    그보다 낮은 채로 Opus 5.5 를 부르면 화면에 원인과 함께 같은 안내가 뜬다.
  - 실행 파일 경로가 특이하면 `CLAUDE_BIN` 환경변수로 지정할 수 있다.

> Claude Code **대화창은 필요 없다.** 앱이 `claude` 명령을 직접 실행하므로 CLI 가 설치되어
> 로그인되어 있기만 하면 된다.

### 다른 컴퓨터에 설치

1. 위 사전 조건 두 가지를 갖춘다.
2. 저장소를 내려받는다.
3. `start.bat` 을 더블클릭한다. 첫 실행이면 패키지를 알아서 내려받는다.

각 컴퓨터가 **그 PC에 로그인된 자기 Claude 계정**으로 동작한다. 최신 내용을 받으려면 켜 둔 창을 닫고 `git pull` 한 뒤
`start.bat` 을 실행한다. 새 패키지(예: 글꼴)가 들어왔으면 그때 알아서 설치한다 — 따로 `npm install` 할 필요가 없다.

## 사용 흐름

### 1단계 — 지문 입력

- **.docx** (권장): 지문별로 영어 본문만 뽑아내고 한글 해석은 걸러낸다.
- **.pdf**: 텍스트로 변환한 결과를 먼저 보여준다. 직접 고친 뒤 지문으로 넘기거나 `.txt`로 저장할 수 있다.
- **.txt**: 그대로 사용.
- **구글 링크**: 드롭존의 **구글 링크로 불러오기**에 구글 문서 링크나, 구글 드라이브에 올린 .docx · .pdf · .txt 파일 링크를 붙여넣는다.
  공유 설정이 **링크가 있는 모든 사용자**여야 한다. 구글 문서는 docx 로 받아 위와 똑같이 처리한다.

지문 분할 기준은 두 가지다.

1. **번호 표시**가 2개 이상 있으면 그것을 기준으로 나눈다.
   - 말머리: `1.` `[2]` `지문 3` `Passage 4` 등
   - 지문 앞의 짧은 꼬리표: `21_기출 예제 01` `PR-21-01` 등. 머리표가 바뀌며 번호가 1부터 다시 시작해도 이어서 나눈다.
2. 번호가 없으면 **영어 → 한글 → 영어** 로 넘어가는 지점과 빈 줄을 기준으로 나눈다.

문항 발문(`…것은?` `…고르시오.`)과 그 뒤의 선지(①②③…)는 본문에서 뺀다.
나뉜 결과는 미리보기에서 확인하고 합치거나 지울 수 있다. 파일 목록에는 어떤 표시로 나눴는지가 보인다.
지문이 들어오면 위의 안내 줄은 접히고 업로드 상자는 한 줄짜리 **파일 더 올리기** 막대로 줄어든다(끌어다 놓기는 그대로).

여기서 **총 표제어 개수**(기본 100), **선택 방식**(직접 / AI 자동), **AI 작업 방식**을 정한다.
화면 아래에 붙은 막대가 고른 설정을 한 줄로 보여주고, 거기서 **표제어 선택 시작 →** 을 누른다.

- AI 작업 방식: **빠르게**(Sonnet 5.5 · low) · **보통**(Opus 5.5 · medium, 기본) · **꼼꼼하게**(Opus 5.5 · high).
  모델과 생각 깊이(effort)를 직접 고르려면 **고급 설정**을 편다 — 모델 Opus 5.5 · Sonnet 5.5, effort low · medium · high · xhigh · max.
- 이 설정은 자동 추출 · 단어장 생성 · 시험지 문항 생성에 모두 쓰인다. 지난번 단어장 생성에 걸린 시간도 함께 보인다.

### 2단계 — 표제어 선택

- 카드는 순서대로 배열되고, **작업 중인 카드만 펼쳐지고 나머지는 한 줄로 접힌다.**
- 단어 **클릭** = 한 단어 선택, **드래그** = 여러 단어(어구) 선택, 선택된 자리를 **다시 클릭** = 해제.
- 카드를 자유롭게 오가며 목표 개수를 맞춘다. 오른쪽 패널에 선택 순서대로 쌓이고 카운트가 올라간다.
- **총 표제어 개수는 이 화면에서 바로 고칠 수 있다.** 카운터의 `/ 100` 자리를 직접 입력하면 목표가 바뀐다.
- 맨 오른쪽 메타 패널: 단어/어구 비율, 품사별 개수(접미사 기반 추정), 지문별 분포.
- **✨ AI 자동 추출** 버튼을 누르면 남은 개수만큼 AI가 골라 회색으로 표시한다. 직접 고른 것은 그대로 유지된다.

> **개수와 분배는 코드가 정한다.** 지문 분량(단어 수)에 비례해 지문별 목표를 먼저 나누고, 지문을 3개씩 묶어
> 동시에 묻는다. 각 묶음에는 목표의 1.5배를 요청해 난이도(1~5)와 함께 받는다. 최종 선별은
> [selectPlan.js](src/lib/selectPlan.js) 가 한다 — 지문마다 자기 몫을 난이도 높은 순으로 채운 뒤,
> 남은 자리를 지문 구분 없이 난이도 높은 순으로 채운다. 자리 겹침·굴절형 중복은 이 단계에서 거른다.
> 몫을 못 채운 지문에만 최대 3회까지 다시 묻고, 그래도 모자라면 몇 개를 채웠는지와 그 이유
> (지문에서 못 찾음 / 자리 겹침 / 중복 / 지문 번호 불일치)를 화면에 그대로 알린다.
> `node tools/select-diagnose.mjs <포트> <개수> [지문파일]` 로 이 동작을 점검할 수 있다.

### 3단계 — 단어장 생성

`파생어·유의어·반의어 생성 →` 을 누르면 확인 창이 뜨고, 승인하면 25개씩 나눠 처리한다.

이미 만든 표가 있으면 확인 창에서 **바뀐 표제어만 생성** / **전체 다시 생성** 중에 고른다. 지금 선택과 겹치는 줄이 있으면
바뀐 것만이 기본이다 — 새로 고른 것과 지난번 응답에서 빠진 것만 AI 로 만들고, 선택에서 뺀 것은 표에서 지우며,
나머지 줄은 표에서 직접 고친 내용까지 그대로 남는다.

생성 규칙:

| 항목 | 규칙 |
| --- | --- |
| **표제어** | 선택한 표현 그대로. 단 현재분사·동명사·과거형·과거완료·3인칭 현재형은 **원형**으로, 복수 명사는 **단수형**으로. 과거분사는 완료형/수동태일 때만 원형으로 바꾸고 그 외에는 유지. `interesting` 처럼 형용사로 굳은 현재분사는 유지 |
| **구문 틀** | 상관어구는 자리표시자로 일반화. `Not only my brother but also my sister` → `Not only A but also B`, `too abstract to grasp` → `too 형용사 to 동사원형`. 관용구·구동사(`sift through`)는 그대로 유지 |
| **품사** | **한 글자**로 표기 — 명·동·형·부·전·접·대·구(어구). 파생어 괄호 안 품사도 같다 |
| **뜻** | 표제어가 **그 출처 문장에서 실제로 쓰인** 한국어 의미 하나. 사전 뜻 나열 금지. 품사에 맞는 어미(명사형·~하다·~한·~하게)를 쓴다 |
| **파생어** | 최대 2개 — 흔히 쓰는 같은 가족 말이 2개 있으면 2개(`speculation` → speculate · speculative), 없으면 비움, **한 줄에 하나씩** `development (명) 발전`. 뜻은 가장 짧게 하나만(받은 뒤 코드가 첫 뜻만 남긴다). 같은 단어 가족의 **흔히 쓰는** 말만, 명사형 &gt; 형용사형 &gt; 동사형 &gt; 부사형 순. **분사형(-ed · -ing)과 뜻을 바꾸는 접두사를 뗀 말(unbearably → bear)은 받은 뒤 코드가 빼고** 표에 "뺌: …" 으로 남긴다. 합성어의 구성 요소 · 어원만 같은 동계어도 프롬프트로 막는다 |
| **유의어** | **되도록 2개**. **고3(수능) 수준**까지 — 쉬운 말을 먼저, 두 번째는 수능 어휘여도 된다. 수능 범위를 넘는 희귀어는 쓰지 않는다. **출처 문장에서 그대로 대체 가능**하고 뜻의 범위가 같아야 한다. 같은 단어장의 다른 표제어는 쓰지 않는다(겹치면 표에 붉게 짚는다) |
| **반의어** | 확실할 때만 최대 2개, **고2가 아는 쉬운 말**로(유의어보다 엄하게). 전체의 **30~50%** 항목에만. 초과분은 confidence가 낮은 것부터 자동으로 정리된다 |
| **표기** | 표제어·파생어·유의어·반의어는 모두 **소문자**. 예외는 구문 틀의 자리표시자 `A`·`B`와 **고유명사**뿐. 프롬프트로 지시하고, 받은 뒤 [aiClient.js](src/lib/aiClient.js)에서 한 번 더 강제한다 |
| **고유명사** | AI 자동 추출에서는 인명·지명·기관명을 **되도록 고르지 않는다**. 꼭 필요해 표제어가 된 경우에는 `properNoun` 으로 표시되어 대문자 표기가 유지된다 |

결과 테이블에서 셀을 직접 고친 뒤 **XLSX**로 내려받는다. 출처(지문 번호)와 출처 문장이 함께 들어간다.
표 위의 칩으로 손볼 줄만 골라 본다 — **AI 누락 · 뜻 없음 · 유의어 없음 · 원형으로 바뀜 · 반의어 있음 · 내가 고친 줄 · 출처 문장 빈칸**, 그리고 지문별.
칩을 누른 순간의 줄을 고정해 보여주므로, 거른 채 고쳐도 그 줄이 사라지지 않는다(칩을 다시 누르면 새로 거른다).
거르기는 보기만 바꾼다 — 번호 · 엑셀 · 시험지는 언제나 표 전체다.
줄 끝의 **×** 는 확인 없이 바로 지우고, 화면 아래에 몇 초 동안 **되돌리기**가 뜬다(만든 시험지까지 함께 돌아온다).
다 고쳤으면 오른쪽 위 **단어시험지 만들기 →** 로 ④ 로 넘어간다.
보이지 않는 시트에 지문 원문과 왕복용 정보(`surface` 등)도 담겨, 나중에 그 파일을 다시 불러올 수 있다.

**요약문 문장은 지문에 넣지 않는다.** 요약문 문항의 문장(`… shows (A) conversation … may (B) personal growth`)은 지문이 아니라
문항 장치라, 지문을 나눌 때 뺀다 — 빈칸 이름표 (A) · (B) 가 둘 이상 든 한 문장이 요약문이다. 그래서 요약문에만 나온 말은 표제어
후보에도 오르지 않고, 출처 문장에 빈칸이 찍히지 않는다. 옛 엑셀의 숨김 지문에서도 뺀다. 그 전에 만든 단어장에 이미 그런 줄이 있으면
표 위에 알리고 출처 칸 아래에 "빈칸 (A) · (B) 남음" 으로 짚는다 — 줄을 지우거나 엑셀에서 문장을 고친다.
순서 배열 문항의 단락 이름표 `(A) So, …` 는 빈칸이 아니라 이름표라 걷는다.

내려받은 파일을 엑셀에서 고쳤다면 **⬆ 고친 엑셀 불러오기**로 다시 올린다. 고친 줄 · 새 줄 · 지운 줄 개수를
먼저 보여주고, **이 내용으로 표 바꾸기**를 누르면 표가 파일 내용으로 바뀐다. 줄을 지우고 번호를 다시 매겨도
줄마다 지문 속 형태가 제자리를 찾는다. 다른 지문에서 나온 단어장이면 붉은 상자로 지금 작업과 견줘 보이고(아래 참고),
버튼도 **다른 작업으로 바꾸기**로 바뀐다.

### 4단계 — 단어시험지 생성

3단계의 **단어시험지 만들기 →** 나 헤더의 **④ 단어시험지 생성**을 누르면 단어장이 확정되고 시험지 화면으로 넘어간다.
표제어를 6개 PART(35문항)에 나눠 담은 배정 결과를 먼저 보여주고, **문항 만들기**를 누르면
PART I·IV 는 단어장만으로 조립하고 II·III·V·VI 는 AI 가 동시에 만든다.
결과는 **시험지**와 **정답·해설지** 두 개의 `.docx` 로 내려받는다.
시험지 머리는 `{연도} {단어장 제목} {반}반   Week {주차}   VOCABULARY TEST   이름: ____________` 한 줄이다.
내보내기 칸에서 연도 · 제목 · 반 · 주차를 채우면 바로 아래 미리보기에 찍힐 모양이 보이고, 비워 둔 칸은 손으로 쓸 빈칸으로 남는다.
제목에 연도나 주차가 이미 들어 있으면(`2027 겨울학기 [실력반] WEEK 09`) 그 값을 머리 칸으로 옮겨 `2027 겨울학기 [실력반] _____반   WEEK 09`
로 찍고, 그 입력 칸은 잠근다 — 두 번 찍히지 않는다.
제목은 1단계의 제목 칸과 같은 값(최대 30자, 비우면 기본 제목)이고 파일 이름과 정답·해설지 제목에도 쓰인다.

화면 위에 붙은 진행 막대가 **배정 → 문항 만들기 → 내려받기** 중 어디까지 왔는지와 다음에 누를 버튼 하나를 늘 보여준다.
문항 수를 못 채운 PART 가 있으면 PART 마다 무엇이 몇 개 모자라고 어디서 채우는지 알려주고, 바로 가는 버튼
(**② 표제어 더 고르기** · **③ 단어장 표에서 채우기** · **배정 다시 하기**)을 붙인다.

AI 가 만든 PART 는 받은 뒤 코드가 다시 검사해 PART 머리에 노랗게 짚는다(막지는 않는다). 검사에 걸린 PART 는
**이 PART 만 다시** 로 그 PART 만 새로 만든다 — 나머지 PART 는 그대로다. 시험지 검수에서 되풀이된 것을 막는 규칙:

| PART | 규칙 (검수 주차) |
| --- | --- |
| III | 첫 글자 힌트가 답을 하나로 좁혀야 한다. 같은 첫 글자의 다른 유의어 · 반의어가 있으면 힌트를 늘린다 — `stretch : s___` 는 shorten 도 맞으므로 `shr___` (W09) |
| IV | 출처 문장에 문항 빈칸 (A)·(B) 가 남은 동사는 쓰지 않는다(옛 단어장). 앞뒤 문장을 붙여도 빈칸 문장은 붙지 않는다 (W07 · W09) |
| V | 소거만으로 풀리지 않게 — **버리는 오답(쉬운 반대말) 1개 이상 + 근접 오답 정확히 1개**. 근접 오답은 정답과 같은 방향이거나 형태가 비슷하지만 문맥 · 연어 · 사실관계로 틀리는 말(ward off 자리의 put off). 정답해설에 오답마다 틀린 이유 한 마디. 만든 뒤 **정답 없이 다시 풀려** 다른 정답으로 읽히는 오답 · 약한 정답을 짚는다(복수 정답 점검). 5문항 중 1~2문항은 고난도. 선택지 낱말은 고3(수능) 이내 (W06~W09) |
| VI | `[이름] spent N years as a [직업] in …` 소개로 시작하지 않고, 덕목을 말로 정리하는 교훈 · 칭찬 문장으로 끝내지 않는다. 도입 · 마무리 방식을 매번 다르게 골라 준다 (W07~W09) |

만든 시험지는 화면 위 **시험지 1 · 2 · 3…** 탭에 보관된다. 다른 단계에 다녀오거나 새로고침해도 남고, 헤더의 **초기화**로 지워진다.

- **배정 다시 하기** — 단어장 순서를 무작위로 섞어 다시 배정한다. 문항을 아직 안 만든 시험지는 그 자리에서 바뀐다.
  문항을 만든 시험지에서는 버튼이 **새 시험지로 다시 배정**이 되어, 그 시험지는 두고 목록에 하나를 더한다.
- 시험지가 둘 이상이면 내려받는 파일 이름 끝에 번호가 붙는다 (`…_시험지_2.docx`). 문서 안의 제목은 그대로다.
- 3단계에서 단어장을 고치면 만든 시험지는 **모두 지워진다**. 필요한 시험지는 먼저 내려받아 둔다.

PART 구성과 출제 규칙은 [quiz-spec.md](quiz-spec.md), 정본 양식은 [public/vocabulary_test_sample.pdf](public/vocabulary_test_sample.pdf).

### 만들어 둔 단어장으로 시험지만 만들기

1단계 화면의 **단어장 불러와서 시험지 만들기**로 이 앱이 내보낸 XLSX 를 열면 ①②③ 을 건너뛰고 ④ 로 간다.
불러온 내용을 확인 패널에서 한 번 보여주고, 지금 작업이 있으면 그것과 견준다.

- 다른 지문에서 나온 단어장이면 **붉은 상자**에 지금 작업과 불러올 파일의 제목 · 지문 · 표제어 선택 · 단어장 줄 수,
  겹치는 표제어 수, 지금 지문에서 찾은 출처 문장 수를 나란히 보이고, 버튼은 **다른 작업으로 바꾸기**가 된다.
- 바꾸면 지금 작업은 한 벌 **보관**된다. 헤더 아래 띠의 **되살리기**로 돌아온다(초기화도 같다). 띠는 새로고침해도 남고,
  되살리면 그때의 작업이 대신 보관되어 잘못 눌러도 다시 돌아올 수 있다. 보관 칸은 하나라 새로 보관하면 그 전 것은 밀려난다.

- 다른 엑셀 파일은 거절한다 (`심화단어장` 시트와 9열 머리글을 본다).
- 숨김 시트가 없는 옛 파일은 출처 문장에서 표제어 형태를 거꾸로 찾아 살린다. 불규칙 변화(`buy`/`bought`)처럼 못 찾은 개수는 화면에 알린다.
- 지문이 들어 있지 않은 파일이면 PART IV 는 출처 문장 하나만 쓴다.

## 디자인

`DESIGN-coinbase.md`(저장소 밖 문서)의 토큰을 [src/styles/global.css](src/styles/global.css) 하나에 CSS 변수로 옮겨 적용했다.

- **색**: 흰 캔버스 + ink(`#0a0b0d`) + 회색 elevation. 브랜드 블루(`#0052ff`)는 주 CTA·활성 단계·표제어 선택 표시에만 쓴다.
- **서체**: 라이선스 서체 대신 문서가 지정한 대체 서체를 자체 호스팅(`@fontsource-variable`) — 본문 Inter, 숫자 JetBrains Mono.
  3단계 단어장 표의 본문은 시험지 영문과 같은 **Lora** 다(한글은 Lora 에 없어 아래 한글 서체가 그린다).
  한글은 Inter에 글리프가 없어 Pretendard → 맑은 고딕으로 폴백한다. 디스플레이는 weight 400 + 음수 자간.
- **형태**: 버튼은 전부 pill(100px), 카드 24px, 패널 16px, 입력 12px. 각진 모서리 없음.
- **깊이**: 헤어라인 1px가 기본, 그림자는 `0 4px 12px rgba(0,0,0,0.04)` 한 단계만. (모달 오버레이만 예외)

작업 화면(2·3단계)은 토큰만 따르고 96px 밴드 리듬은 쓰지 않는다 — 문서의
*"Density lives behind login walls, not on marketing"* 원칙에 따라 지문 카드·표는 작업 밀도를 유지한다.
`hero-band-dark` 시그니처 패턴은 1단계 지문 입력 화면 상단에 적용했다.

선택 표시는 팔레트 안에서 처리한다 — **직접 고른 표제어는 브랜드 블루**, **AI가 제안한 것은 회색**(`surface-strong`).
매매 신호용 green/red는 문서 지침대로 배경 채우기에 쓰지 않고, 진행 막대의 달성/초과 표시에만 쓴다.

## 배포에 대해

지금 구조는 **이 PC 전용**이다. `claude -p` 는 로컬에 로그인된 계정으로 실행되므로 서버에 올려 여러 사람이 쓰게 할 수 없다.
웹으로 배포하려면 `server/claudeBridge.js` 를 Anthropic API 키를 쓰는 서버(예: Cloudflare Worker)로 교체하면 된다.
프롬프트(`server/prompts.js`)와 나머지 코드는 그대로 쓸 수 있다.
